# OBD2 ESP32 CYD

เกจ OBD-II ติดรถ บนบอร์ด **ESP32-2432S028 (CYD, "Cheap Yellow Display")** เชื่อมกับอะแดปเตอร์ **ELM327 ผ่าน Bluetooth Classic (SPP)**
แสดงค่าจากรถบนจอสัมผัส 2.8" 320×240 และเปิด **หน้าเว็บแดชบอร์ด** ให้ดูจากมือถือหรือคอมพิวเตอร์ได้ (ผ่าน WiFi บ้าน หรือ AP ของตัวบอร์ด)

- แสดง **เฉพาะค่าจริงจากรถ**: ไม่มีค่าหรือค่าเก่าเกิน 7 วินาที แสดง `--`, ECU ไม่รองรับ PID นั้น แสดง `N/A`
- อ่าน / ลบรหัสข้อผิดพลาด (DTC) พร้อมคำอธิบายอังกฤษและไทย
- **UI v4 แบบ automotive smart gauge:** shift light, มาตรวัดรอบพร้อมตัวเลขหน้าปัดและเครื่องหมาย peak, ลูกศรแนวโน้ม,
  หน้า FOCUS (ค่าเดียวขนาดใหญ่ + กราฟ 60 วินาที), หน้า TRIP (สถิติการเดินทาง + จับเวลา 0–100 km/h), ปัดซ้าย/ขวาเปลี่ยนหน้า
- เตือนน้ำหล่อเย็นร้อนเกินแบบเต็มจอ, แถบเตือน (toast) เมื่อแบต/น้ำมันต่ำหรือสัญญาณหลุด, เสียงเตือนเมื่อรอบถึง shift light
- ธีม DARK / LIGHT / AUTO (ตามแสงจากเซนเซอร์ LDR หรือตามเวลา), ฟอนต์ Chakra Petch รองรับภาษาไทย
- ค้นหาและจับคู่อะแดปเตอร์ Bluetooth จากหน้าจอได้เลย ไม่ต้องแก้โค้ด

> **ทดสอบกับรถจริงแล้ว:** Toyota Vios 2011 (2026-10-15) เชื่อมต่อได้ และอ่าน RPM, ความเร็ว, น้ำหล่อเย็น, อากาศเข้า, แบตเตอรี่, คันเร่ง และโหลดได้
> ระดับน้ำมัน (PID `012F`) ECU รุ่นนี้ไม่รองรับ
>
> **UI v4 ทดสอบบนบอร์ดจริงแล้ว** (2026-10-18) ผู้พัฒนา upload แล้วยืนยันว่าใช้งานได้
>
> **ทดสอบกับตัวจำลองแล้ว** (2026-10-21) CYD เชื่อมต่อตัวจำลองใน `simulator/` ได้ ขึ้น ONLINE และค่าที่แสดงตรงกับที่ตัวจำลองส่ง
>
> **รองรับจอ 2 แบบ** (2026-10-30): env `cyd` (ILI9341) และ `cyd_st7789` (ST7789) ทดสอบ `cyd_st7789` บนบอร์ด ST7789 จริงแล้ว ภาพถูกต้อง

## ใน repo นี้มีเฟิร์มแวร์ 2 ตัว

```
OBD_ESP32-CYD/
├─ (root)       เฟิร์มแวร์ CYD    → upload ลง ESP32-2432S028 (เกจติดรถ)
└─ simulator/   ตัวจำลอง ELM327  → upload ลง ESP32 DevKit (ทดสอบที่โต๊ะโดยไม่ต้องใช้รถ)
```

ทั้งสองเป็นโปรเจกต์ PlatformIO แยกกัน: build ตัว CYD ที่โฟลเดอร์หลัก และ build ตัวจำลองในโฟลเดอร์ `simulator/`
ใช้ตัวจำลองแทนอะแดปเตอร์ในรถได้เลย ฝั่ง CYD ไม่ต้องแก้โค้ด (ดู [ทดสอบโดยไม่ต้องใช้รถ](#ทดสอบโดยไม่ต้องใช้รถ))

## ฮาร์ดแวร์

| อุปกรณ์ | หมายเหตุ |
|---|---|
| บอร์ด ESP32-2432S028 (CYD) | ESP32 + จอ 2.8" 320×240 (**ILI9341** หรือ **ST7789** แล้วแต่รุ่น ดู [เลือกชิปจอ](#3-เลือกชิปจอ-env)) + จอสัมผัส resistive XPT2046 + LED RGB + LDR + ขั้วลำโพง |
| อะแดปเตอร์ ELM327 แบบ **Bluetooth Classic** | ใช้แบบ BLE หรือ WiFi ไม่ได้ ค่าเริ่มต้นชื่อ `OBDII` รหัส `1234` (เปลี่ยนได้ในหน้า SET) |
| ลำโพงเล็ก (ไม่บังคับ) | ต่อที่ขั้ว SPEAK บนบอร์ด (GPIO26 ผ่านวงจรขยายบนบอร์ด) |
| สาย USB + ไฟเลี้ยง 5V ในรถ | |
| ESP32 DevKit (ไม่บังคับ) | สำหรับตัวจำลองใน `simulator/` ต้องเป็น ESP32 รุ่นดั้งเดิม (ESP32-S3 / C3 ไม่มี Bluetooth Classic) |

### ขาที่ใช้ (จาก [`include/board_config.h`](include/board_config.h))

| ส่วน | ขา |
|---|---|
| จอ TFT (HSPI) | MISO 12, MOSI 13, SCLK 14, CS 15, DC 2, ไฟหลังจอ 21 (PWM) |
| จอสัมผัส XPT2046 (VSPI) | SCK 25, MISO 39, MOSI 32, CS 33 (IRQ 36 ไม่ใช้ อ่านแบบ polling) |
| LED RGB (active-LOW) | แดง 4, เขียว 16, น้ำเงิน 17 |
| ลำโพง | 26 |
| เซนเซอร์แสง (LDR) | 34 |

> **ห้ามใช้ GPIO21 ต่อเซนเซอร์เพิ่ม** เพราะเป็นขาไฟหลังจอ (จอจะกะพริบ) ถ้าจะต่ออุปกรณ์เพิ่มให้ใช้ GPIO27 / GPIO22

## เริ่มต้นใช้งาน

### 1. ติดตั้งเครื่องมือ

ใช้ [PlatformIO](https://platformio.org/) (ส่วนขยาย PlatformIO IDE ใน VS Code หรือ `pio` CLI) ไลบรารีที่ต้องใช้ (`bodmer/TFT_eSPI`) จะถูกดาวน์โหลดเองตอน build

### 2. ตั้งค่า WiFi (ไม่บังคับ)

คัดลอก `include/secrets.h.example` เป็น `include/secrets.h` แล้วแก้ค่า

```cpp
inline constexpr char WIFI_SSID[] = "MyHomeWiFi";
inline constexpr char WIFI_PASSWORD[] = "...";
#define CYD_AP_PASSWORD "change-me-123"   // รหัส AP ของบอร์ด 8-63 ตัวอักษร (แนะนำให้ตั้ง)
```

- ESP32 ใช้ WiFi ย่าน 2.4 GHz เท่านั้น
- ไม่มีไฟล์นี้ก็ build ได้ บอร์ดจะเปิด AP ของตัวเองทันที
- `secrets.h` อยู่ใน `.gitignore` รหัสผ่านจะไม่ขึ้น git

### 3. เลือกชิปจอ (env)

CYD มีจอ 2 แบบที่หน้าตาเหมือนกัน แต่ใช้ชิปคนละตัว ต้อง build ด้วย env ให้ตรงกับบอร์ด:

| env | ชิปจอ | บอร์ดที่มักเป็น |
|---|---|---|
| `cyd` (ค่าเริ่มต้น) | ILI9341 | CYD รุ่นเดิม มีช่อง **micro-USB ช่องเดียว** |
| `cyd_st7789` | ST7789 | CYD รุ่นใหม่ มี **USB-C** (หรือ 2 ช่อง USB-C + micro-USB), จอรหัส TPM408-2.8 |

ไม่แน่ใจว่าเป็นแบบไหน: ลอง `cyd` ก่อน ถ้าภาพเพี้ยน เลื่อน หรือขาดครึ่งจอ ให้เปลี่ยนเป็น `cyd_st7789` (Serial จะพิมพ์ `[DISP] ILI9341` หรือ `[DISP] ST7789` ตอนบูต)
ค่าที่เก็บในบอร์ด (calibrate, อะแดปเตอร์, ธีม) ไม่หายเมื่อสลับ env

**VS Code:** คลิกชื่อ env ที่แถบสถานะด้านล่าง (`env:cyd`) แล้วเลือก `env:cyd_st7789` ก่อนกด Upload

### 4. Build, upload และดู Serial

รันที่โฟลเดอร์หลักของ repo (เฟิร์มแวร์ CYD) เลือก `-e` ตามชิปจอ

```bash
pio run -e cyd -t upload --upload-port COM3
```

```bash
pio run -e cyd_st7789 -t upload --upload-port COM3
```

```bash
pio device monitor -b 115200 --port COM3
```

(เปลี่ยน `COM3` เป็นพอร์ตของบอร์ดคุณ) โปรแกรมใช้ partition `huge_app.csv` เพราะ Bluetooth Classic ทำให้โปรแกรมใหญ่เกินพาร์ทิชันปกติ
ทั้งสอง env ล็อกเวอร์ชันไว้ (`espressif32@7.0.1` = Arduino core 2.0.17, `TFT_eSPI@2.5.43`) ทุกเครื่อง build ได้ผลเหมือนกัน

### 5. แก้การแสดงผล (สีกลับ / แดงสลับน้ำเงิน / ภาพกลับหัว)

จอบาง batch ใช้ env ถูกแล้วแต่สียังเพี้ยน ไม่ต้องแก้โค้ด: ไปหน้า **SET** หัวข้อท้าย ๆ แล้วแตะแถว

| แถว | ใช้เมื่อ |
|---|---|
| **Invert colors** | สีกลับเป็นภาพเนกาทีฟ (พื้นดำกลายเป็นขาว) |
| **Swap red/blue** | สีแดงกลายเป็นน้ำเงิน (เช่นสีส้มของมาตรวัดกลายเป็นฟ้า) |
| **Flip 180°** | ติดตั้งจอกลับหัว จอสัมผัสหมุนตามให้เอง ไม่ต้อง calibrate ใหม่ |

ค่าจำถาวร แยกตามชิปจอ ถ้าปรับแล้วอ่านจอไม่ออก พิมพ์ `f` ใน Serial เพื่อกลับเป็นค่าเริ่มต้น

### 6. Calibrate จอสัมผัส

เปิดครั้งแรกบอร์ดจะเข้าหน้า calibrate เอง ให้แตะเป้า 4 มุมทีละจุด (ใช้เล็บหรือปากกาปลายมนจะแม่นกว่านิ้ว)
ค่าเก็บถาวรใน flash ไม่ต้องทำใหม่ ถ้าต้องการทำใหม่ให้ **กดค้างแถว RECALIBRATE TOUCH 2 วินาที** ในหน้า SET (แท็บเฟือง) หรือพิมพ์ `c` ใน Serial

### 7. เชื่อมต่อกับรถ

1. เสียบ ELM327 ที่ช่อง OBD-II ของรถ (ส่วนใหญ่อยู่ใต้คอนโซลฝั่งคนขับ) แล้วเปิดสวิตช์กุญแจหรือติดเครื่อง
2. บนบอร์ด แตะแท็บ **SET** (ไอคอนเฟืองขวาล่าง) → แตะแถว **Adapter** เพื่อเปิดหน้า **SCAN** (ค้นหาประมาณ 10 วินาที)
3. แตะอุปกรณ์ในรายการ (อะแดปเตอร์ที่ชื่อเหมือน OBD จะขึ้นก่อนพร้อมป้าย `OBD`) บอร์ดจะจำชื่อ + MAC แล้วเชื่อมต่อทันที
   - หาไม่เจอ: กด **MANUAL** เพื่อพิมพ์ชื่อหรือ MAC (`AA:BB:CC:DD:EE:FF`) ด้วยคีย์บอร์ดบนจอ
   - รหัสจับคู่ไม่ใช่ `1234`: แตะแถว **PIN** เพื่อแก้
4. แถบบนขึ้น `BT CONNECTED` สีเขียว และ LED เป็นสีเขียวเมื่อเริ่มได้ค่าจริง
   ถ้าต่อ Bluetooth ได้แต่ยังไม่ติดเครื่อง จะขึ้น `WAITING FOR ECU`

ครั้งต่อไปบอร์ดจะเชื่อมต่อกับอะแดปเตอร์เดิมเอง และถ้าหลุดจะลองใหม่ทุก 4 วินาที

## ทดสอบโดยไม่ต้องใช้รถ

ใช้ ESP32 DevKit อีกตัวเป็นตัวจำลอง: ทำตัวเป็นอะแดปเตอร์ ELM327 ชื่อ `OBDII` (PIN `1234`) ต่อกับ "รถจำลอง"
ที่เปลี่ยนสถานการณ์ได้ (เดินเบา, ขับในเมือง, ออกตัว 0–100, รอบสูง, น้ำร้อน, แบตต่ำ, น้ำมันใกล้หมด, มีรหัสข้อผิดพลาด ฯลฯ)
ควบคุมจาก **หน้าเว็บบนมือถือ** (`http://obd-sim.local`) ได้: เปลี่ยนสถานการณ์, ปรับค่าเองด้วยแถบเลื่อน, เลือกรหัสข้อผิดพลาด, จำลอง ECU ไม่ตอบ
รายละเอียดทั้งหมดอยู่ใน [`simulator/README.md`](simulator/README.md)

1. Upload ตัวจำลองลง ESP32 DevKit

   ```bash
   cd simulator
   pio run -t upload --upload-port COM8
   ```

2. Upload เฟิร์มแวร์ CYD ตามหัวข้อ [เริ่มต้นใช้งาน](#เริ่มต้นใช้งาน)
3. บน CYD: แท็บ **SET** → **Adapter** → รอค้นหาเสร็จ → แตะแถว `OBDII` ที่เป็นตัวจำลอง (ดู MAC ให้ตรงกับที่ตัวจำลองพิมพ์ออก Serial ตอนบูต)
4. CYD ขึ้น `BT CONNECTED` และแสดงค่า เปลี่ยนสถานการณ์จากหน้าเว็บของตัวจำลอง, คำสั่งตัวอักษรเดียวใน Serial หรือปุ่ม BOOT

> **ต้องเลือกจากหน้า SCAN ทุกครั้งที่เปลี่ยนบอร์ด:** CYD จำ **MAC** ของอะแดปเตอร์ไว้ ESP32 แต่ละตัวมี MAC ไม่เหมือนกัน
> และอะแดปเตอร์จริงในรถก็มักชื่อ `OBDII` เหมือนกัน ถ้าไม่เลือกใหม่ CYD จะพยายามต่อตัวเดิมต่อไป

## หน้าจอบนบอร์ด

ดีไซน์ v4: [`design_handoff_cyd_obd_gauge/README_v4.md`](design_handoff_cyd_obd_gauge/README_v4.md)
และ prototype ที่กดเล่นได้ในเบราว์เซอร์ [`Smart Gauge CYD v4.html`](design_handoff_cyd_obd_gauge/Smart%20Gauge%20CYD%20v4.html)

ทุกหน้า (ยกเว้น SCAN, คีย์บอร์ด และ calibrate) มี **แถบสถานะ** ด้านบน (IP ของหน้าเว็บ + ป้ายสถานะ Bluetooth)
และ **แถบแท็บ 5 ช่อง** ด้านล่าง: DRIVE · FOCUS · TRIP · FAULT · เฟือง (SET)

| ท่าทาง | ผล |
|---|---|
| แตะ | ปุ่มทำงานเมื่อ **ปล่อยนิ้วบนปุ่มเดิม** (เลื่อนนิ้วออกก่อนปล่อย = ยกเลิก) |
| กดค้าง 2 วินาที | ปุ่มที่ทำสิ่งสำคัญ (มีแถบเติมให้เห็น): ล้าง peak, RESET, RESET TRIP, CLEAR, RECALIBRATE |
| ปัดซ้าย / ขวา | ในพื้นที่เนื้อหาของ DRIVE / FOCUS / TRIP / FAULT: ไปหน้าถัดไป / ก่อนหน้า (วนรอบ) |
| ลากขึ้น / ลง | เลื่อนรายการในหน้า SET |

| หน้า | หน้าที่ |
|---|---|
| **DRIVE** | **Shift light** 15 ช่องด้านบน (เขียว → เหลือง → แดง, ถึงรอบที่ตั้งไว้กะพริบแดง), มาตรวัดรอบ 270° (สเกล 8,000, redline 6,500, ตัวเลขหน้าปัด 0–8) พร้อม **ขีด peak** และข้อความ `PEAK`, ความเร็วตัวเลขใหญ่, การ์ด 4 ใบ: COOL °C (MAX), BATT V (MIN), FUEL % (MIN), THR % (MAX) พร้อม **ลูกศรแนวโน้ม 5 วินาที** / แตะการ์ดหรือมาตรวัด = ไปหน้า FOCUS ของค่านั้น, กดค้างมาตรวัด = ล้าง peak |
| **FOCUS** | ค่าเดียวขนาดใหญ่ (RPM, SPEED, COOL, BATT, FUEL, THR, LOAD, IAT เลือกด้วย ‹ ›), MIN / AVG / MAX, **กราฟ 60 วินาที** พร้อมเส้นประที่เกณฑ์ / RESET กดค้างล้างสถิติของค่านั้น |
| **TRIP** | TIME, DIST, AVG, MAX, MAX RPM, MOVING / **จับเวลา 0–100 km/h**: กด ARM → จอดนิ่ง (READY) → ออกตัว (GO) → ถึง 100 แสดงผลและเวลาดีสุด / RESET TRIP กดค้าง |
| **FAULT** | ปุ่ม **READ** อ่าน DTC (Mode 03) พร้อมสถานะไฟ MIL, แสดง 3 รหัสต่อหน้า (มีปุ่มเปลี่ยนหน้า), คำอธิบายอังกฤษ + ไทย, แถบสีแดง = รหัสร้ายแรง (P03xx จุดระเบิด, P0118, P0217) / ปุ่ม **CLEAR** กดค้าง 2 วินาทีเพื่อลบรหัส (Mode 04) แล้วอ่านซ้ำให้ |
| **SET** | รายการเลื่อนได้: Adapter (เปิดหน้า SCAN), PIN (เปิดคีย์บอร์ด), CONNECT, Theme, Backlight, Sound (OFF / LOW / MID / HIGH), **Shift light** (− / + ทีละ 250 รอบ), **Overheat °C** (− / + เกณฑ์น้ำร้อน 95–115), **Invert colors / Swap red/blue / Flip 180°** (แก้การแสดงผล), RECALIBRATE TOUCH (กดค้าง), เวอร์ชันเฟิร์มแวร์ + ชิปจอ |
| **SCAN** | ค้นหาอุปกรณ์ Bluetooth รอบตัว แสดงความแรงสัญญาณ, ชื่อ, MAC, ป้าย `OBD` / `SAVED` เรียง OBD ก่อน > มีชื่อก่อน > สัญญาณแรงก่อน / ปุ่ม BACK, ‹ ›, MANUAL, RESCAN |
| **Keyboard** | คีย์บอร์ด a–z 0–9 `- _ .` พร้อม SHIFT, SPACE, DEL, ESC, OK ชื่อยาวได้ 32 ตัว, PIN 16 ตัว |
| **Calibrate** | แตะเป้า 4 มุม ถ้าจุดที่แตะไม่เป็นสี่เหลี่ยม (คลาดเกิน 25 px) จะให้ทำใหม่ |
| **ALERT** | ขึ้นทับทุกหน้าเมื่อน้ำหล่อเย็น ≥ เกณฑ์ (ค่าเริ่มต้น 105 °C): พื้นแดงกะพริบ 1 Hz, `OVERHEAT` + อุณหภูมิ + ข้อความไทย, เสียงเตือนซ้ำ แตะที่ใดก็ได้เพื่อรับทราบ จะเตือนอีกครั้งได้เมื่อลดต่ำกว่าเกณฑ์ − 3 °C แล้วกลับมาเกินใหม่ |

**แถบเตือน (toast)** ขึ้นใต้แถบสถานะ 4 วินาที (แตะเพื่อปิด): `BATTERY LOW` (< 12.2 V), `FUEL LOW` (< 10 %),
`OBD LINK LOST` (สัญญาณหลุดเอง), `CODES CLEARED`, ผลจับเวลา `0–100 IN x.x s`

สถิติ (MIN / AVG / MAX), peak, กราฟ, trip และเวลา 0–100 ดีสุด **ไม่เก็บถาวร** ล้างเมื่อปิดเครื่อง

## หน้าเว็บแดชบอร์ดและ API

เปิดที่ `http://<IP ของบอร์ด>` หรือ `http://cyd-obd.local`
IP แสดงที่มุมซ้ายบนของจอ: `192.168.x.x` = ต่อผ่าน WiFi บ้าน, `AP 192.168.4.1` = ต่อผ่าน AP ของบอร์ด

หน้าเว็บมีค่าจากรถ (มาตรวัด + การ์ด อัปเดตทุก 0.6 วินาที), อ่าน / ลบ DTC (ปุ่มลบต้องกดค้าง 2 วินาที), ตั้งชื่อ / MAC / PIN ของอะแดปเตอร์ และแถบความสว่างจอ
ฟอนต์ Chakra Petch โหลดจาก Google Fonts ถ้าไม่มีอินเทอร์เน็ต (เช่นโหมด AP) จะใช้ฟอนต์ของระบบแทน

### การเชื่อมต่อเครือข่าย

1. มี `WIFI_SSID` ใน `secrets.h` → ลองต่อ WiFi ภายใน 15 วินาที ไม่ได้ → เปิด AP `CYD-OBD`
2. ต่อ WiFi ได้แล้วหลุดเกิน 30 วินาที → เปิด AP สำรอง
3. อยู่โหมด AP และไม่มีใครต่ออยู่ → ลองต่อ WiFi ใหม่ทุก 60 วินาที (เช่นเปิด hotspot มือถือทีหลัง)
4. ต่อ WiFi ได้ → ขอเวลาจาก NTP (`pool.ntp.org`, UTC+7) สำหรับธีม AUTO แบบตามเวลา

### API

| Endpoint | หน้าที่ |
|---|---|
| `GET /` | หน้าแดชบอร์ด |
| `GET /api/status` | ค่าจากรถทั้งหมด (`null` = ไม่มีค่า), รายการ PID ที่ไม่รองรับ (`na`), สถานะ Bluetooth / เครือข่าย / IP, ความสว่างจอ, heap ที่เหลือ |
| `GET /api/dtc` | ผลอ่าน DTC ล่าสุด: `state` (IDLE / BUSY / DONE / ERROR), `msg`, `mil`, `count`, `codes[]` |
| `POST /api/dtc/read` | สั่งอ่าน DTC |
| `POST /api/dtc/clear` | สั่งลบ DTC ต้องส่ง `confirm=yes` และจะถูกปฏิเสธ (`409`) ถ้ารถกำลังวิ่ง |
| `GET /api/config` | ชื่อ, MAC และ `pinSet` ของอะแดปเตอร์ (ไม่ส่งค่า PIN ออกมา) |
| `POST /api/config` | ตั้ง `name` (≤ 32) และ `pin` (≤ 16) แล้วเชื่อมต่อใหม่ |
| `POST /api/backlight` | ตั้ง `value` ความสว่างจอ (10–100 %) |
| `POST /api/reconnect` | เชื่อมต่อ Bluetooth ใหม่ |

**ความปลอดภัย:** คำสั่ง `POST` ทุกตัวต้องมี header `X-CYD: 1` และต้องเรียกผ่าน IP ของบอร์ดหรือ `cyd-obd.local` เท่านั้น (กัน CSRF และ DNS rebinding) ไม่อย่างนั้นได้ `403`

ตัวอย่าง

```bash
curl http://cyd-obd.local/api/status
```

```bash
curl -X POST -H "X-CYD: 1" -d "confirm=yes" http://cyd-obd.local/api/dtc/clear
```

## การสื่อสารกับรถ (ELM327 / OBD-II)

บอร์ดเป็นฝ่าย master เชื่อมไปหาอะแดปเตอร์ (ชื่อ Bluetooth ของบอร์ดคือ `CYD-OBD`)
ถ้ามี MAC (เลือกจากหน้า SCAN หรือพิมพ์ MAC) จะเชื่อมตรงไม่เกิน ~10 วินาที ถ้ามีแต่ชื่อ ไลบรารีต้องค้นหาชื่อก่อน (นานสุด ~30 วินาที)

**ขั้นเริ่มต้น ELM327:** `ATZ` (รีเซ็ต) → `ATE0` `ATL0` `ATS0` `ATH0` (ปิด echo / LF / ช่องว่าง / header) → `ATAT1` (timeout อัตโนมัติ) → `ATSP0` (เลือก protocol อัตโนมัติ)
→ `0100` (ให้ค้นหา protocol และอ่าน PID 01–20 ที่ ECU รองรับ) → `ATDPN` (ดูว่าเป็น CAN หรือไม่) → `0120` (PID 21–40 ถามเฉพาะเมื่อ ECU บอกว่ามี)

ถ้าตอนเชื่อมต่อยังไม่ติดเครื่อง (ECU ไม่ตอบ `0100`) บอร์ดจะถามรายการ PID ที่รองรับใหม่เองเมื่อ ECU เริ่มตอบ

### ค่าที่อ่าน

| ค่า | คำสั่ง | สูตร |
|---|---|---|
| รอบเครื่อง | `010C` | (256·A + B) / 4 rpm |
| ความเร็ว | `010D` | A km/h |
| น้ำหล่อเย็น | `0105` | A − 40 °C |
| คันเร่ง | `0111` | A · 100 / 255 % |
| โหลดเครื่องยนต์ | `0104` | A · 100 / 255 % |
| อากาศเข้า | `010F` | A − 40 °C |
| ระดับน้ำมัน | `012F` | A · 100 / 255 % |
| แรงดันแบตเตอรี่ | `ATRV` | อะแดปเตอร์วัดเอง ไม่ต้องพึ่ง ECU |

ลำดับการถามคือ RPM สลับกับค่าอื่นทุกครั้ง (`RPM, SPEED, RPM, THR, RPM, LOAD, ...`) เพื่อให้มาตรวัดรอบลื่น และข้าม PID ที่ ECU ไม่รองรับ
คำสั่งอ่าน / ลบ DTC ได้คิวก่อนการอ่านค่าเสมอ

**DTC:** `0101` อ่านสถานะ MIL → `03` อ่านรหัส (รองรับคำตอบหลายบรรทัดของ CAN และรหัสซ้ำจากหลาย ECU, เก็บได้สูงสุด 16 รหัส) / `04` ลบรหัส แล้วอ่านซ้ำเพื่อยืนยัน
มีคำอธิบายของรหัสที่พบบ่อย 37 รหัส รหัสอื่นแสดงเป็น "Manufacturer specific" (P1xxx–P3xxx) หรือ "Generic code"

**การจัดการเมื่อหลุด:** คำสั่ง init ไม่ตอบ 3 ครั้ง หรือการอ่านค่าหมดเวลา 5 ครั้งติดกัน → ตัดการเชื่อมต่อแล้วลองใหม่ ส่วน `NO DATA` จาก ECU จะพัก 250 ms แล้วถามต่อ

### ธีม

- **DARK** (พื้นดำ ตัวอักษรส้มอำพัน) และ **LIGHT** (พื้นครีม มีเส้นขอบการ์ด) จำความสว่างจอแยกกัน (ค่าเริ่มต้น 70 % / 95 %)

  หรือตั้ง `AUTO_THEME_USE_LDR = false` เพื่อใช้เวลา 06:00–18:00 = LIGHT (ต้องต่อ WiFi ที่มีอินเทอร์เน็ต)

## สถาปัตยกรรมโปรแกรม

โปรแกรมทั้งหมดอยู่ใน [`src/main.cpp`](src/main.cpp) (~4,200 บรรทัด) แบ่งงานเป็น 3 ส่วนที่ทำงานพร้อมกัน

```
core 0  obdTask (FreeRTOS)      Bluetooth SPP + ELM327 state machine + ค้นหาอุปกรณ์ (SCAN)
                                  NoConfig → BtStart → Connecting → Init → Online
                                                 ↑                       │ หลุด / ไม่ตอบ
                                                 └────── Backoff ←───────┘
                                  (Scanning ระหว่างเปิดหน้า SCAN)
core 1  loop()                  จอสัมผัส (ทุก 10 ms) → ปุ่ม / ปัด / ลาก → วาดเฉพาะส่วนที่เปลี่ยน (ทุก 200 ms)
                                  + สถิติ / trip / กราฟ / 0–100 / แถบเตือน (คำนวณจากค่าที่อ่านได้ ทุก 200 ms)
                                  + LED, Serial, WiFi / AP / mDNS, เว็บเซิร์ฟเวอร์
core 1  soundTask               เล่นเสียงจากคิว (ไม่หน่วง UI)
```

- ทุกคำสั่งถึง ELM327 เป็นแบบ "ส่งแล้วรอจนเจอ `>` หรือหมดเวลา" ใน task แยก จอสัมผัสจึงลื่นแม้ระหว่างเชื่อมต่อ
- ค่าที่แชร์ระหว่าง task (ค่า PID, ผล DTC, ค่าตั้ง, ผลค้นหา) ป้องกันด้วย `volatile` และ `portMUX` critical section
- หน้า SCAN ไม่ใช้ `SerialBT.discover()` แต่ลงทะเบียน GAP callback ของ ESP-IDF เอง (ได้ชื่อ, RSSI และถามชื่ออุปกรณ์ที่ไม่บอกชื่อได้) เสร็จแล้วเริ่ม SerialBT ใหม่เพื่อคืน callback ให้ไลบรารี
- จอสัมผัสอ่าน XPT2046 ผ่าน SPI ด้วยโค้ดเอง: เลือกค่าเฉลี่ยของ 2 ใน 3 sample ที่ใกล้กันที่สุด, debounce (กด 2 / ปล่อย 3 ครั้ง), calibrate เชิงเส้นพร้อมตรวจแกนสลับ, กรอง EMA
- ทุกสีบนจอมาจาก struct ธีม (`THEME_DARK` / `THEME_LIGHT`) และมี `static_assert` ตรวจค่า RGB565 กับดีไซน์ v3
- รายการหน้า SET วาดผ่าน viewport ของ TFT_eSPI (ตัดขอบไม่ให้ทับแถบสถานะ / แท็บ) และวาดใหม่ทุกครั้งที่เลื่อน 2 px
- หน้าเว็บส่งแบบ chunked: HTML ส่วนหัว → ค่าจากเฟิร์มแวร์ (เกณฑ์น้ำหล่อเย็น, เวอร์ชัน, คำอธิบาย DTC ไทย) → HTML ส่วนท้าย

## แก้ปัญหาเบื้องต้น

| อาการ | สิ่งที่ควรลอง |
|---|---|
| `BT DISCONNECTED` ตลอด, Serial ขึ้น `connect failed` | อะแดปเตอร์มีไฟไหม, ชื่อ / PIN ถูกไหม, ลองเลือกจากหน้า SCAN (ได้ MAC เชื่อมเร็วกว่า), ตรวจว่าเป็น Bluetooth Classic ไม่ใช่ BLE |
| ต่อตัวจำลองไม่ได้ ทั้งที่ตัวจำลองเปิดอยู่ | ดูบรรทัด `[BT] connecting to "OBDII" <MAC>` ใน Serial ของ CYD เทียบกับ MAC ที่ตัวจำลองพิมพ์ตอนบูต ถ้าไม่ตรง ให้เลือกตัวจำลองใหม่จากหน้า SCAN |
| ต่อได้แต่ขึ้น `WAITING FOR ECU` / LED เหลือง | เปิดสวิตช์กุญแจหรือติดเครื่อง, ดู Serial ว่า `protocol probe` ได้คำตอบไหม |
| การ์ดขึ้น `N/A` | ECU ของรถคันนี้ไม่รองรับ PID นั้น (เช่นระดับน้ำมันบน Vios 2011) |
| ภาพเลื่อน ขาดครึ่งจอ หรือมีขยะตามขอบ | build ผิด env: สลับ `cyd` ↔ `cyd_st7789` (แก้ตอนใช้งานไม่ได้) |
| สีเนกาทีฟ / แดงสลับน้ำเงิน / ภาพกลับหัว | หน้า SET → Invert colors / Swap red/blue / Flip 180° (พิมพ์ `f` ใน Serial เพื่อกลับค่าเดิม) |
| แตะจอไม่ตรง | กดค้างแถว RECALIBRATE TOUCH ในหน้า SET 2 วินาที หรือพิมพ์ `c` ใน Serial แล้ว calibrate ใหม่ |
| ปัดเปลี่ยนหน้าไม่ติด | ปัดให้ยาวกว่า 50 px และเร็ว (ภายใน 0.7 วินาที) ในแนวนอน เริ่มจากพื้นที่เนื้อหา (ไม่ใช่แถบบน/แท็บ) |
| เปิดหน้าเว็บไม่ได้ | ดู IP ที่มุมซ้ายบนของจอ, `cyd-obd.local` อาจใช้ไม่ได้บน Android บางรุ่น ให้ใช้ IP แทน |
| `POST` ได้ `403` | ใส่ header `X-CYD: 1` และเรียกผ่าน IP หรือ `cyd-obd.local` |
| ธีม AUTO ไม่เปลี่ยน | พิมพ์ `l` ดูค่า LDR ในที่สว่าง / มืด แล้วปรับเกณฑ์ใน `app_config.h` |

## ข้อจำกัดที่รู้อยู่

- **ทดสอบกับรถจริงแค่คันเดียว** (Toyota Vios 2011) รถที่ใช้ protocol อื่นยังไม่ได้ทดสอบ
- **จับเวลา 0–100 คลาดได้ประมาณ 0.5–1 วินาที** เพราะความเร็วถูกอ่านเป็นช่วงๆ (ไม่ได้เพิ่มความถี่การอ่านระหว่างจับเวลา)
- ระยะทางในหน้า TRIP คำนวณจากความเร็ว × เวลา ใช้ดูคร่าวๆ ไม่ใช่ odometer
- **เกณฑ์ LDR (`100` / `400`) ยังไม่ได้วัดจากบอร์ดจริง** ควรใช้คำสั่ง `l` วัดแล้วปรับ
- ถ้าไม่ได้ตั้ง `CYD_AP_PASSWORD` AP จะใช้รหัสเริ่มต้นใน `app_config.h` ซึ่งไม่ปลอดภัย (Serial เตือนตอนเปิด AP)
- หน้า SCAN แสดงชื่ออุปกรณ์ได้เฉพาะตัวอักษร ASCII (ตัวอื่นเป็น `?`)
- การลบ DTC จากหน้าจอบนบอร์ดไม่ได้เช็กว่ารถหยุดอยู่ (เช็กเฉพาะคำสั่งจากหน้าเว็บ)
- namespace ของ `Preferences` ยังชื่อ `lab9` (ถ้าเปลี่ยน ค่าที่เก็บไว้จะหาย ต้อง calibrate และตั้งค่าใหม่)
- หน้าเว็บยังเป็นดีไซน์เดิม (ยังไม่ได้ปรับตาม v4)
